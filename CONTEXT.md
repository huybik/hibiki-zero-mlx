# Hibiki MLX — project context

MLX runtime for Kyutai's **Hibiki-Zero** (simultaneous speech-to-speech + speech-to-text translation, FR/ES/PT/DE → EN, 3B hierarchical transformer + Mimi codec @ 12.5 Hz) on Apple Silicon, aimed at the **iPhone 80 ms/frame budget**. The upstream PyTorch stack was purged; the MLX q4 path is the product. **All 5 phases of `docs/refactor_plan.md` are done**: P1 restructure, P2 inference sweep (`reports/inference_matrix.md`), P3 Track B parallel head *scaffold* (`reports/parallel_head_smoke.md` — AR head stays default; parallel needs a scaled run before it ships), P4 finetune refactor (`docs/finetune.md`), P5 iPhone-readiness (phone artifact + `scripts/check_swift_compat.py` + `reports/iphone_budget.md`). Chosen phone config: **Hibiki-M 1B q4** (FR→EN), 3B stays the Mac/teacher model.

- Upstream: https://github.com/kyutai-labs/hibiki-zero · https://arxiv.org/abs/2602.11072v1 · weights CC BY-NC-SA 4.0.
- Python env: conda base at `/opt/homebrew/Caskroom/miniconda/base/bin/python` (py3.13; mlx 0.31, torch 2.12, moshi 0.2.13, rustymimi 0.4.1; `moshi-mlx/` and `hibiki_mlx` installed editable).

## Layout (repo root = `code/`)
- `hibiki_mlx/` — THE runtime package (installed editable). `pipeline.py` = pipelined q4 inference `load(dir, quant)`/`run()`/`make_mimi()`/`resolve_weights_dir("3b"|"1b"|path)`; honors each model's config (dep_q, n_q, delays, conditioners). No `sys.path` hacks; weights anchor on repo root (`hibiki_mlx.pipeline.W = <root>/weights`, `MODEL_DIRS`).
- `main.py` — thin CLI: `python main.py <audio> [--model 3b|1b] [--quant q4|q4-depq3]` (file → `translations/<stem>_translated.wav` + `.txt`, 3-thread pipelined) or `python main.py --mic` (encoder/LM/decoder threads; live critical path = LM step: 3B ~22 ms, 1B ~15 ms on M4).
- `moshi-mlx/` — **vendored fork of `moshi-mlx` 0.3.0** (installed editable). Owns all hibiki-zero deltas: `hidden_scale=6` + `kv_repeat=2` (GQA) + `rope_concat` + the learned per-slice depformer output **LayerNorm** (`depformer_norms.{i}`) — without the LayerNorm the audio babbles (silence-in test: correct model rms≈0.06, buggy rms≈0.13 peak≈1.23). Also handles Hibiki-M's float `hidden_scale=4.125`. Phase-2 deltas: `DepFormer.sample` fast path (cfg_coef==1) threads KV functionally through one `mx.compile`d step per slice; `make_rot_cache` caps `RotatingKVCache` at `cfg.context` (KV at cap: 3B 344 MB / 4 min window, 1B 66 MB / 40 s). **q4 must be regenerated after touching the depformer** (LayerNorm stays bf16; nn.quantize skips non-Linear). Runs on mlx 0.31 despite the fork's `<0.27` pin.
- `scripts/` — conversion/verification/benchmark only: `convert_mlx_q4.py` (PyTorch LM → `weights/hibiki.q4.safetensors`, `nn.quantize(bits=4, group_size=32)`), `convert_hibiki_m_mlx_q4.py` (stages `weights/hibiki-m-mlx-q4/`, 1.125 GB q4 LM), `convert_depq3.py` (q4-depq3 variants), `verify_mlx_q4.py` (gate: leon.wav → `translations/leon_mlx_q4.wav`), `bench.py` (per-stage ms / RT / size / iPhone projection / `--silence` gate), `check_swift_compat.py` (device-free: validates a staged artifact the way `moshi_mlx.run_inference`/moshi-swift load it — gs32 q4 naming/shapes via strict reload, config keys, tokenizer+mimi load), `push_mlx_q4.py`, `push_hibiki_m_mlx_q4.py`. **Keep `group_size=32`** — stock moshi-mlx/moshi-swift hardcode gs32 for `.q4.safetensors`.
- `assets/samples/` — test clips: `leon.wav` (~64 s FR Olympics), `crepes.mp3`, 12 s cuts.
- `weights/` (gitignored) — 3B checkpoint (`config.json`, `hibiki-pytorch-77f82164@110.safetensors` 5.8 GB, `hibiki.q4.safetensors` 2.2 GB, mimi 367 MB, tokenizer) + `hibiki-m-mlx-{bf16,q4}/`.
- `finetune/` — PyTorch LoRA training stack (uses the `moshi` pip package; PyTorch eval helpers live in `finetune/hibiki_helpers.py`, relocated from the deleted upstream `hibiki_zero` package).
- `remote_dataset/` — CoVoST2 + FLEURS eval data & scripts. `training-data/` — PhoMT TTS pipeline. `docs/`, `vision/`.
- Published artifacts: [`huybik/hibiki-zero-3b-mlx-q4`](https://huggingface.co/huybik/hibiki-zero-3b-mlx-q4) (weights + portable stock-pkg patch shim), [`huybik/hibiki-1b-mlx-q4`](https://huggingface.co/huybik/hibiki-1b-mlx-q4) `@9649ed0`.

## Runtime facts (M4 Pro; full matrix in `reports/inference_matrix.md`)
- Pipelined file path **3B ~3.0× / 1B ~4.1× RT**: encoder thread streams `encode_step` ahead → main-thread GPU LM step → decoder thread. rustymimi releases the GIL; each thread needs its **own** `rustymimi.Tokenizer` ("Already borrowed" panic otherwise). Codec threads queue **numpy** (not mx) arrays — lazy mx graphs are bound to the creating thread's stream and mlx ≥0.27 refuses cross-thread eval.
- Per-frame GPU LM: **3B q4 ≈ 22 ms** (main 11.9 + depformer 10.2), **1B q4 ≈ 14.7 ms** (main 7.4 + depformer 7.3); mimi codec (CPU) enc ~18 / dec ~17 ms, fully hidden by the pipeline. Depformer stays **sequential-launch-bound** — the compiled per-slice fast path (Phase 2) bought −18% dep / −9% frame on the 3B, quantization buys 0 on M4; only the parallel-codebook head (Phase 3 / distill plan) removes the serial passes. Projected iPhone LM step at 0.5× M4 scale: 1B ~29 ms, 3B ~44 ms vs the 80 ms budget.
- Quant variants: `q4-depq3` (slice transformers q3, emb/linear_out stay q4) = 3B 2.21 GB / 1B 1.05 GB, same speed, small BLEU cost (1B 28.4→26.8). Quantizing depformer emb+linear_out to q3 makes the 3B babble-loop through the tail flush — don't.
- Tail flush: input ends → feed `tail_s` (8 s) silence to flush the ~6 s translation lag, early-stop after `PAD_STOP`=12 pad frames (sitting longer hallucinates). Text temp **0.4** default (audio 0.8): kills spurious cold-start openers, BLEU 22.1→25.8 (text feeds back autoregressively; greedy 0.0 over-collapses).
- Gates for runtime changes: `python scripts/verify_mlx_q4.py` coherent, and silence-in via `scripts/bench.py --model {3b,1b} --silence` (10 s zeros → rms < 0.10, peak < 1.1; healthy: rms≈0.0002, peak≈0.012; exact value is seed-dependent).
- Codec-fidelity: decoding generated tokens at fewer codebooks degrades gracefully (mel-dist 0.049@8, 0.105@4). Inference-time depformer truncation is NOT a faithful dep_q=8 preview (feedback goes OOD).

## Phone artifact + iPhone budget (Phase 5)
`weights/hibiki-m-mlx-q4/` is the staged standalone phone artifact (config.json `moshi_name`→q4 file, `hibiki-mlx-dc2cf5a5@80.q4.safetensors` 1.13 GB gs32, `.q4-depq3` 1.05 GB variant staged alongside via `convert_depq3.py --model 1b`, mimi 0.38 GB, tokenizer, model card). Ships the **AR head**. `scripts/check_swift_compat.py weights/hibiki-m-mlx-q4/` → **7/7 PASS** (config keys, `moshi_name`.q4, gs32 on 298 tensors, strict gs32 q4 reload == `run_inference.py`, tokenizer 48k, mimi nq=8). The **depq3 variant is our-pipeline-only** — its name isn't `.q4.safetensors`, so stock moshi-swift wouldn't q4-load it; the q4 file is THE swift-compatible one. Publish is a manual authed step (`push_hibiki_m_mlx_q4.py`, not re-pushed here).
- **Budget (`reports/iphone_budget.md`, projections — no device):** scale = A18/M4-Pro GPU throughput, default 0.5× (band 0.4–0.6). M4 LM step: 1B AR 15.1 ms (main 8.0 + dep 7.0), 3B AR 22.2 ms (12.3 + 9.9), 1B+parallel ~13.4 ms (par head 5.3 ms measured on 3B, conservative). Projected iPhone @0.5×: **1B AR 30 ms, 1B parallel 27 ms, 3B AR 44 ms — all FIT 80 ms**; worst case @0.4× 1B AR ~38 ms. Memory (AR): 1B ~1.8 GB (LM 1.13 + KV 0.07 + mimi 0.38 + ~0.2 act), 3B ~3.4 GB. 1B fits a base-6 GB iPhone app budget (~2.5–3 GB); 3B needs 8 GB Pro + extended-memory entitlement. **Blocking true realtime (device-side, honest):** no moshi-swift on-device build in loop; ANE-vs-GPU placement (vision targets ANE, current path is Metal GPU; AR depformer maps poorly to ANE → parallel head); sustained thermals; launch-bound dispatch may scale worse than bandwidth on a phone GPU.

## Track B — parallel codebook head (`distill/`, Phase 3 scaffold)
Self-distill a **parallel** head to replace the AR depformer's 16 sequential launch-bound slices (distill_plan §3–9). Frozen main = teacher; only the new head trains; keep cb16 (§6). **Scaffold + smoke distill done; quality needs a scaled run — AR head is the default, parallel is opt-in.**
- `distill/dump_teacher.py` — inference-only, resumable shards of `(transformer_out fp16, text token, N teacher tokens, N×vocab teacher logits fp16)` via a capture hook on `DepFormer.sample` (`model.depformer.capture=True` → `.last_logits/.last_tokens`). Smoke: 30 CoVoST2 fr clips / 2289 frames / 152 MB (~66 KB/frame; ~2.9 GB/h — go top-k past ~5 h).
- `distill/parallel_head.py` — vectorised delay-pattern head: per-codebook `w_in/w_out/cb_emb/norm` stacked, applied by batched einsum/gather (few launches, not 370); shared 6-layer bidirectional trunk over the 16 codebook positions; codebook k conditions on its own prev-frame token (delay-1). `num_passes` knob (1 default; 2–4 iterative-refine placeholder). Warm-start from AR depformer where shapes match. 227 M params bf16.
- `distill/train_head.py` — `KL(teacher‖student,T)+CE`, Adam, `value_and_grad` on **head params only**, clip-clean split, head-only checkpoint. Smoke: full-train loss 21.4→2.9 over 500 steps; overfit-32-frames → 0.044 (capacity/grad sanity).
- Integration: `HIBIKI_HEAD=parallel [HIBIKI_HEAD_CKPT=… HIBIKI_HEAD_PASSES=N]` → `pipeline.load()` attaches the bf16 head (after `nn.quantize`, so head stays bf16); `Lm._sample` routes to `parallel_head.sample` (owns its prev-token streaming state, reset after warmup); `bench.py` times it.
- **Measured (3B, M4, clean):** codebook head **12.70→5.28 ms (−58%)**, LM total **25.9→18.5 ms (−29%)**, 3.1→4.3× RT live. Head is now bandwidth-bound (227 M bf16) not launch-bound → q4 head + param-shrink is the path to the 1–4 ms target. Gates: AR default still coherent + silence-in PASS (rms 0.0002); parallel path text coherent (text bypasses the head), silence-in PASS (rms 0.064) even at smoke scale.

## Finetune (Track A, Vietnamese) — Phase 4 done
`finetune/`: `build_pairs.py` (FLEURS → `pairs/{split}.jsonl` + deterministic `val16`/`val128` gate subsets) **and `fetch_phomt.py` (HF `anquachdev/PhoMT-en-vi-speech` → `remote_dataset/phomt_en_vi/` wavs + `pairs/phomt_train.jsonl`; enumerates all `data/*.parquet` via `list_repo_files` — the dataset scaled to 148k rows / 224 VI-h measured on 2026-07-22 — `--limit N` caps pairs, vi>25 s dropped)** → `cache_codes.py` (Mimi/text codes, coarse target delay; PhoMT → `cache/phomt_train/`) → `train_lora.py` (**`--cache-dir` takes multiple dirs; shards pooled, e.g. FLEURS `cache/train` + `cache/phomt_train` = 2438 samples, no FLEURS re-encode**; `--max-frames N` drops over-long cached samples — use **280** (22 s) to avoid the long-tail MPS OOM) → `validate_lora.py` / `eval_lora.py` (batched greedy eval, loop metrics, BLEU/chrF/WER) → `autoresearch.py` (fixed trial harness, TSV protocol, primary metric val chrF). **All shared logic (model+LoRA build, adapter save/load, cached-shard dataset, teacher-forced losses, greedy generation, metrics, schedule primitives) lives once in `finetune/common.py`**; the three scripts are thin wrappers (eval_lora 670→141, validate_lora 191→106 lines). See `docs/finetune.md`.
- Freeze map: LoRA on `LMModel.transformer` + optional full `text_linear` (`--train-text-head`) + audio-head LoRA on `depformer_in`/`linears` (`--train-audio-heads`), zero-init new LoRA (random-init spikes loss). Supervise prefix-delay text pads, mask tail padding; text loss weight ~5. **`--full-finetune`** = paper-faithful full-model SFT (unfreeze all, single LR group, `model_step*.safetensors` `target=full`); it's the scaled CUDA run (won't fit MPS) — **use `--dtype float32` (bf16 master weights round away lr~1e-5 Adam updates; on CUDA the forward runs under bf16 autocast + fused AdamW automatically) and `--keep-checkpoints` (default 2) since full saves are ~35 GB (model + AdamW state)**. LoRA stays the MPS plumbing probe; `eval_lora`/`validate_lora` auto-detect via `common.load_finetuned`.
- **Schedules (Phase 4, piecewise `value@fraction` of total steps; static flags = single point):** loss weights `--text-weight-schedule "5@0,2@0.6"` / `--audio-weight-schedule`; replay `--replay-weight-schedule "300@0,100@0.5"` (rebuilds the replay sampler at boundaries, needs `--replay-ids`); per-group LR `--lr-schedule` / `--text-head-lr-schedule` / `--audio-head-lr-schedule` + `--warmup-steps`. **Selection:** `--eval-every N` runs batched greedy val eval (default val128) and saves `adapter_best.safetensors` on chrF improvement. All `torch.mps.*` gated behind `is_mps(device)` → CUDA runs clean.
- Findings so far: best 16-row result 11/16 exact (`vn_lora_short16_audioheads_lr1e4_from_s800`); staged replay 300→100 is best fixed-gate row (chrF 9.20, seen3 3/3) but val output still loops — not real translation yet. Protocol: seen3/short16 smoke-only, **val128 for real decisions**, full 1449 last; 5/16-row deltas are noise. MPS train `--dtype bfloat16 --batch-size 2 --grad-accum-steps 2` (batch 4 spikes to 47.5 GB); eval batch 8. One hypothesis per commit, keep only if val chrF improves.
- **MPS memory gotcha:** the pool has 262 distinct seq-lengths; MPS caches a Metal kernel graph per shape → wired GPU footprint balloons to 26 GB (phys peak 48 GB) and swap-thrashes even though torch reports ~9.6 GB. `collate_cached` **buckets frame length to a multiple of 32** (`FRAME_BUCKET`, 9 shapes) → phys peak 48→19 GB, ~9 s/step; loss-neutral (pad = -1 = zero_token_id, masked). CUDA is unaffected. Resume uses `torch.load(weights_only=False)` (checkpoint args hold Path objects).
- **PhoMT+FLEURS combined run `finetune/runs/vn_phomt_combined/` (rank 32, lr 1e-4→3e-5, text-weight 5→2, text+audio heads): BSOD'd at step 605 ≈ end of epoch 1** (609 steps/epoch @ eff-batch 4; `sort_by_length=true` → longest clips up to 51 s in the final batches → MPS 8.6→37.7 GB, over the 36 GB cap → panic; hence `--max-frames 280`). Latest checkpoint step 500; its val128 greedy is empty/looping English ("the idea of the idea of…"), **not translating**.
- **Diagnosis (paper §4.6/§4.2.3, see `docs/vi_training_plan.md`): recipe matches theirs (SFT + CE text/audio + randomized coarse delay) — two gaps: data scale (~7.8 h vs their 850 h floor, ~100×) and method (paper does full-model SFT; we ran LoRA r32).** Fix = scale synthetic speech from the full PhoMT text corpus (~2.9M pairs, only 992 synthesized) to 50–150 h + real vi source (CommonVoice/VIVOS), then **full-model SFT (`--full-finetune`) on CUDA** — LoRA r32 has no evidence of capacity for a new source language, and full finetune removes that confound. Distill+RL are downstream, later.
- In-training greedy eval (`--eval-every`) is too slow on MPS at val128 (each batch decodes full-length pre-EOS) — prefer `--eval-every 0` then a final `eval_lora.py --stop-on-eos`.

Not a train↔eval mismatch (errors show in pure TF). Empirically justifies the full-finetune switch (LoRA on frozen backbone can't route a new source language). ## PhoMT synthetic speech (`training-data/`)
Kokoro TTS EN + VieNeu VI generation; `af_nicole` at 1.35×, `am_michael` 1.10×; `upload.py` filters EN/VI duration ratio 0.4–1.8. The published/consumed artifact is HF `anquachdev/PhoMT-en-vi-speech` (48 kHz wav, `en`/`vi` text + `audio_en`/`audio_vi`), pulled into training by `finetune/fetch_phomt.py` (see Finetune above). vieneu ≥ 3.2 batches natively on the PyTorch backend (CUDA **and** MPS) — `infer_batch` flattens chunks across texts through its static-batching engine (`max_batch_size=32`), so the old `BatchedVieneuTTS` wrapper is gone (it also called a `_resolve_v3_ref` API removed in 3.2.3). **VI speaker diversity:** `build_voice_bank.py` clones 34 VIVOS speakers (one 6–12 s ref each, VIVOS `genders.txt` labels; CC BY-NC-SA) into `<data>/voice_bank/vi_voices.json`; `pipeline.py` auto-registers it → 48-voice VI pool (22f/26m). Enrollment needs the `torchaudio.load`→soundfile shim (torchaudio ≥ 2.10 delegates to torchcodec, which has no torch-2.13 build). `VI_WORKERS > 1` shards a language across processes with per-worker manifests merged into `manifest.csv` after success. Data root is `paths.py`'s `PHOMT_DATA_DIR` env (default `D:\Code\datasets` on Windows, `/Volumes/data/datasets` on macOS — external disk, system disk hosts swap — `~/datasets` elsewhere). `TTS_DEVICE="auto"` resolves cuda > mps > cpu (`PYTORCH_ENABLE_MPS_FALLBACK=1` set for Kokoro's missing MPS ops). Runs in its own conda env **`phomt-data`** (py3.12, torch 2.13 — MPS ops are native Metal kernels in 2.13, free Apple-Silicon speedup; torchaudio 2.11 installed `--no-deps` since the project ended at 2.11 and VieNeu only needs its pure-Python kaldi fbank; deps in `training-data/README.md`), not the repo's base env. vieneu 3.2.3 renamed the preset voices — `VIE_NEU_VOICES` mirrors the package's `voices_v3_turbo.json` (14 voices, 7f/7m). **MPS fast path (`vieneu_mps_patch.py`, applied in `load_tts`): rewrites `V3TurboBatchEngine.generate_batch` — tensorized repetition penalty (kills ~153k `.item()` syncs/batch), device-side EOS (sync every 8 frames), one batched MOSS codec decode, fp16 LM (`VI_FP16`), plus `infer_batch_voices` (per-text voices → global length-sorted batches across all 48 voices, replacing per-voice grouping). 2026-07-30 hyper-opt pass: `_MPSFastDecoder` (static-KV hand-rolled Qwen3 decode step replacing HF per-step forward — DynamicCache torch.cat re-copied the whole KV every frame; KV-length bucketed to 64 / alloc to 128 to bound MPS shape-cache churn; sdpa `enable_gqa` works on MPS), lean acoustic frame (functional-cat KV + fused sdpa beat a static-buffer variant 3× at this size — tiny tensors are cat-cheap), fused decode-slot embedding (stacked audio-emb table, one gather+sum), sort-free sampling (top-k → nucleus within 25 candidates → exponential-race argmax; distribution-identical, no full-vocab sort/multinomial). Backbone step 27→7 ms/frame, acoustic frame 9.8→7 ms. ## Gotchas
- Input must be FR/ES/PT/DE. `sphn.read(sr=24000)` resamples on load, so 16 kHz wavs run directly.
- `nn.quantize` predicate must skip modules whose last dim isn't divisible by 32 (Hibiki-M conditioners).
- HF xethub CDN times out: `HF_HUB_DISABLE_XET=1 HF_HUB_DOWNLOAD_TIMEOUT=120`.
